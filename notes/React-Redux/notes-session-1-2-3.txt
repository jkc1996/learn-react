✅ What is React.StrictMode?

React.StrictMode is a development-only tool that helps you:

Detect bugs early. Detect unsafe patterns. Prepare your app for future React features. Enforce best practices. It does NOT affect production builds.

In React 18, StrictMode intentionally runs certain things twice:

Component render

useEffect setup + cleanup

useState initializer

useMemo / useCallback initializers

Example:
useEffect(() => {
  console.log('Effect');
  return () => console.log('Cleanup');
}, []);

In StrictMode (DEV):
Effect
Cleanup
Effect


This is intentional, not a bug.

Why?

To detect:

Side effects in render

Non-idempotent logic

Missing cleanup

Unsafe subscriptions

"<>...</> is called a Fragment shorthand"

Two ways to write a Fragment:

1️⃣ Shorthand Fragment
<>
  <h1>Title</h1>
  <p>Description</p>
</>

2️⃣ Explicit Fragment
<React.Fragment>
  <h1>Title</h1>
  <p>Description</p>
</React.Fragment>


Both do exactly the same thing in most cases.

🟢 When to Use Fragment (<>...</>)

Use fragments when:

✔ You need multiple sibling elements
✔ You do not want extra <div> in DOM
✔ You are structuring clean semantic HTML
✔ You don’t need props on the wrapper

🔴 When NOT to Use Shorthand Fragment
❌ Case 1: When you need a key (VERY IMPORTANT)

Shorthand fragment cannot accept props.

❌ Invalid:

<>
  key={id}
  <Item />
</>


✔ Correct:

<React.Fragment key={id}>
  <Item />
</React.Fragment>


Common in lists:

items.map(item => (
  <React.Fragment key={item.id}>
    <dt>{item.label}</dt>
    <dd>{item.value}</dd>
  </React.Fragment>
));
