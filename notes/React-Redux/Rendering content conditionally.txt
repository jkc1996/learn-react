TOPIC: CONDITIONAL RENDERING IN REACT (3 WAYS)

0. PRE-REQUISITE (THE STATE VARIABLE)
---------------------------------------------------------
For all the examples below, assume we have this state variable defined at the top of our component. This tracks which tab the user clicked.

const [selectedTopic, setSelectedTopic] = useState(); 
// initially undefined/null (so nothing is selected)


1. OPTION A: THE TERNARY OPERATOR (? :)
---------------------------------------------------------
Use this for quick "If-Else" checks directly inside the HTML.

Syntax:
{ condition ? (Show_This) : (Else_Show_This) }

Example:
{!selectedTopic ? <p>Select a topic</p> : <div id="tab-content">...</div>}


2. OPTION B: THE LOGICAL AND OPERATOR (&&)
---------------------------------------------------------
Use this for "If-Only" checks (Show if true, otherwise nothing).

Syntax:
{ condition && (Component_To_Render) }

How it works:
- If True: Renders the component.
- If False: Renders nothing (short-circuits).

Example:
{selectedTopic && <div id="tab-content">...</div>}


3. OPTION C: USING VARIABLES (THE "CLEANEST" WAY)
---------------------------------------------------------
Use this when your logic is complex or you want to keep your return statement simple.

How it works:
Instead of putting logic inside the JSX `return (...)`, you calculate what to show BEFORE the return statement using standard JavaScript `if` / `else`.

Step-by-Step:
1. Create a variable (`let tabContent`) and give it a Default Value (the "Else" case).
   let tabContent = <p>Please select a topic.</p>;

2. Check your condition using a normal `if` statement.
   if (selectedTopic) {
      // If true, overwrite the variable with the main content
      tabContent = (
         <div id="tab-content">
            <h3>{EXAMPLES[selectedTopic].title}</h3>
            ...
         </div>
      );
   }

3. Render the variable in the return statement.
   return (
      <div>
         {tabContent}  <-- Look how clean this is!
      </div>
   );

WHY USE THIS?
- Readability: Your main HTML doesn't look messy with `?`, `:`, and `&&` symbols everywhere.
- Flexibility: You can use complex logic (switch statements, multiple if-else) which is hard to do inside JSX.
