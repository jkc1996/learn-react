TOPIC: REACT STATE & THE "RULES OF HOOKS"

1. THE PROBLEM (NORMAL VARIABLES)
---------------------------------------------------------
- Scenario: You use `let name = "Alice"` and update it to "Bob".
- Result: The variable changes in memory, but the UI stays "Alice".
- Why: React does not know the data changed, so it does not re-run (re-render) the component function.

2. THE SOLUTION (USESTATE)
---------------------------------------------------------
- Scenario: You use `const [name, setName] = useState("Alice")`.
- Action: You call `setName("Bob")`.
- Result: 
  1. Updates the value to "Bob".
  2. Triggers a RE-RENDER (wakes up React to run the function again and update the HTML).

3. THE "GOLDEN RULE" OF HOOKS (WHERE TO PUT THEM)
---------------------------------------------------------
React Hooks (useState, useEffect, etc.) have strict placement rules.

✅ DO:
- Call them at the very TOP LEVEL of your React Component function.
- Example:
  function MyComponent() {
     const [count, setCount] = useState(0); // ✅ Correct
     
     return <div>...</div>
  }

❌ DO NOT:
- Do NOT call them inside loops, conditions, or nested functions.
- Do NOT call them outside the component.

WHY?
React relies on the *order* of hooks to keep track of which state belongs to which variable. 
If you put a hook inside an `if` statement, it might run sometimes and not others, messing up the order and breaking the app.

BAD EXAMPLE (Avoid This):
  function MyComponent() {
     if (someCondition) {
        const [count, setCount] = useState(0); // ❌ CRASH! Don't do this.
     }
     
     function nestedHelper() {
        const [name, setName] = useState("Alice"); // ❌ WRONG! No nested functions.
     }
  }
